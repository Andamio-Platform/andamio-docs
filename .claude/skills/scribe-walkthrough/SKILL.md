# Scribe Walkthrough Skill

Convert Scribe (scribehow.com) autogenerated markdown into polished MDX walkthrough pages for the Andamio docs guides section.

## Invocation

`/scribe-walkthrough` — Show dashboard (default)

### Commands

| Command | Description |
|---------|-------------|
| `/scribe-walkthrough` | Show dashboard with progress summary |
| `/scribe-walkthrough status` | Same as dashboard |
| `/scribe-walkthrough next` | Recommend the next walkthrough to convert |
| `/scribe-walkthrough convert <id>` | Convert a specific walkthrough from raw Scribe markdown |
| `/scribe-walkthrough add` | Add a new walkthrough to the tracker |

## Dashboard Format

When showing the dashboard, display:

1. **Summary counts**: completed / total, by status
2. **Progress by role**: Courses, Projects, Contributors
3. **Walkthrough list**: Table with id, title, role, status, notes
4. **Next recommendation**: Which walkthrough to convert next and why

Example:
```
## Scribe Walkthrough Dashboard

**Progress**: 2/7 completed | 5 awaiting Scribe recordings

### By Role
- Getting Started: 1/1 done
- Courses: 1/3 done
- Projects: 0/2
- Contributors: 0/2

### All Walkthroughs
| ID | Title | Role | Status | Notes |
|----|-------|------|--------|-------|
| getting-started | Getting Started | general | completed | ... |
| ... | ... | ... | ... | ... |

### Next Up
Recommend: `managing-students` — completes the course owner flow
```

## Statuses

| Status | Meaning |
|--------|---------|
| `completed` | MDX page has full walkthrough content from Scribe conversion |
| `needs-update` | Completed but Scribe recording needs to be redone (UI changed, etc.) |
| `in-progress` | Currently being converted |
| `awaiting-scribe` | Placeholder exists, waiting for Scribe recording |

### Status Transitions
```
awaiting-scribe → in-progress → completed
completed → needs-update → in-progress → completed
```

## Convert Workflow

When running `/scribe-walkthrough convert <id>`:

1. **Check tracker**: Verify the walkthrough exists and has a Scribe URL or the user provides raw markdown
2. **Read the raw Scribe markdown**: User pastes it or provides the Scribe share URL
3. **Read current placeholder**: Load the existing MDX file to understand its structure
4. **Read conversion rules**: Load `conversion-rules.md` for the full transformation reference
5. **Strip boilerplate**: Remove Scribe headers, footers, navigation tips, alert boxes
6. **Group steps**: Analyze the micro-granular Scribe steps and propose logical sections
7. **Present grouping plan**: Show the user the proposed section breakdown and get approval
8. **Generate MDX**: Apply all conversion rules, preserving frontmatter and placeholder structure
9. **Update tracker**: Set status to `completed`, record step/section counts, date, Scribe URL

### Important Rules
- **Always present the grouping plan before generating MDX** — never skip this step
- **Preserve the existing placeholder's frontmatter** — title, description stay as-is unless obviously wrong
- **Match the tone of completed walkthroughs** — direct, concise, imperative for actions
- **Include Scribe attribution callout** at the end of the walkthrough section
- **Keep the Related section** from the placeholder intact
- See `conversion-rules.md` for the complete transformation reference

## Add Workflow

When running `/scribe-walkthrough add`:

1. Ask for: title, id (slug), role, file path, description
2. Create entry in `walkthrough-tracker.json` with status `awaiting-scribe`
3. Confirm the placeholder MDX file exists (or note that one needs to be created)
