# Transaction Types

The TX State Machine supports 17 transaction types across courses, projects, and user operations. Each type has specific metadata requirements and database update behaviors.

<Callout type="info">
Use `GET /api/v2/tx/types` to retrieve the current list of valid transaction types from the API.
</Callout>

## Course Transactions

| TX Type | Description | Auto DB Update |
|---------|-------------|----------------|
| `course_create` | Create new course on-chain | Links `policy_id` to course record |
| `course_enroll` | Student enrolls in course | Updates enrollment status |
| `modules_manage` | Add/remove course modules | Confirms module status |
| `teachers_update` | Update teacher list | Syncs teacher list to DB |
| `assignment_submit` | Student submits assignment | Updates commitment status |
| `assessment_assess` | Teacher assesses submission | Updates acceptance/rejection |
| `credential_claim` | Student claims credential | None (on-chain only) |

## Project Transactions

| TX Type | Description | Auto DB Update |
|---------|-------------|----------------|
| `project_create` | Create new project on-chain | Registers project in DB |
| `project_join` | Contributor commits to task | Confirms task commitment |
| `tasks_manage` | Add/remove project tasks | Links `task_hash` to DB records |
| `task_submit` | Contributor submits work | Updates commitment status |
| `task_assess` | Manager assesses submission | Records acceptance/rejection |
| `blacklist_update` | Update contributor blacklist | None (on-chain only) |
| `project_credential_claim` | Claim project credential | None (on-chain only) |
| `treasury_fund` | Add funds to treasury | None (on-chain only) |

## User Transactions

| TX Type | Description | Auto DB Update |
|---------|-------------|----------------|
| `access_token_mint` | Mint access token | None (on-chain only) |

## Metadata Requirements

Most transactions only require `tx_hash` and `tx_type`. Some transactions need additional metadata to link on-chain data to database records.

### No Metadata Required

These transactions extract all needed information from the JWT or the on-chain data:

```typescript
// Course create - owner_alias auto-captured from JWT
await fetch('/api/v2/tx/register', {
  method: 'POST',
  headers: { 'X-API-Key': API_KEY, 'Authorization': `Bearer ${jwt}` },
  body: JSON.stringify({
    tx_hash: txHash,
    tx_type: 'course_create'
  })
});
```

Transaction types with no metadata required:
- `course_create`
- `course_enroll`
- `modules_manage`
- `teachers_update`
- `assignment_submit`
- `assessment_assess`
- `credential_claim`
- `task_submit`
- `task_assess`
- `blacklist_update`
- `project_credential_claim`
- `treasury_fund`
- `access_token_mint`

### Project Create

Requires project title (and optionally description):

```typescript
await fetch('/api/v2/tx/register', {
  method: 'POST',
  headers: { 'X-API-Key': API_KEY, 'Authorization': `Bearer ${jwt}` },
  body: JSON.stringify({
    tx_hash: txHash,
    tx_type: 'project_create',
    metadata: {
      title: 'My Project',
      description: 'Optional project description'
    }
  })
});
```

### Project Join (Task Commit)

Requires the task hash to link the commitment:

```typescript
await fetch('/api/v2/tx/register', {
  method: 'POST',
  headers: { 'X-API-Key': API_KEY, 'Authorization': `Bearer ${jwt}` },
  body: JSON.stringify({
    tx_hash: txHash,
    tx_type: 'project_join',
    metadata: {
      task_hash: 'the-on-chain-task-hash'
    }
  })
});
```

### Tasks Manage

Requires task information for linking:

```typescript
await fetch('/api/v2/tx/register', {
  method: 'POST',
  headers: { 'X-API-Key': API_KEY, 'Authorization': `Bearer ${jwt}` },
  body: JSON.stringify({
    tx_hash: txHash,
    tx_type: 'tasks_manage',
    metadata: {
      tasks: [
        { task_hash: 'hash1', title: 'Task 1' },
        { task_hash: 'hash2', title: 'Task 2' }
      ]
    }
  })
});
```

## Implementation Status

<Callout type="warn">
Some transaction types are not yet fully implemented in the Gateway.
</Callout>

### Fully Implemented (13 of 17)

All course transactions and most project transactions work end-to-end.

### Pending Implementation

| TX Type | Status | Notes |
|---------|--------|-------|
| `managers_manage` | Blocked | Waiting for Andamioscan event endpoint |
| `course_enroll` | Partial | UpdateDB not fully implemented |
| Task leave/update | Not started | Future functionality |

These limitations don't affect frontend development - you can still register these transactions. The Gateway will track them, but the automatic database update may not execute.
