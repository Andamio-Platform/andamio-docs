# API Integration

This guide covers authentication and API setup for integrating with the Andamio Gateway.

> **API Reference**: For endpoint schemas and parameter details, see the [API Docs](https://api.andamio.io).

## Authentication

All Andamio API requests require two authentication headers:

| Header | Purpose |
|--------|---------|
| `X-API-Key` | Application-level (your app) |
| `Authorization: Bearer <jwt>` | User-level (wallet signature) |

### API Key (Application)

```
X-API-Key: <your-api-key>
```

API keys identify your application. Get one from [app.andamio.io/api-setup](https://app.andamio.io/api-setup). See [Getting Started](/docs/getting-started) for the full setup flow.

### JWT (User)

```
Authorization: Bearer <jwt>
```

JWTs authenticate individual users via wallet signature:

```typescript
const API = "https://api.andamio.io/api/v2";

// 1. Request a challenge
const challengeRes = await fetch(`${API}/auth/challenge`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ address: walletAddress }),
});
const { challenge } = await challengeRes.json();

// 2. User signs the challenge
const signature = await wallet.signData(walletAddress, challenge);

// 3. Exchange signature for JWT
const verifyRes = await fetch(`${API}/auth/verify`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ address: walletAddress, signature }),
});
const { jwt } = await verifyRes.json();
```

JWTs expire after a configurable period (typically 24 hours).

## Making Requests

Once authenticated, include both headers in all requests:

```typescript
const headers = {
  "Content-Type": "application/json",
  "X-API-Key": APP_API_KEY,
  "Authorization": `Bearer ${userJwt}`,
};

// Example: List user's courses
const res = await fetch(`${API}/course/owner/courses/list`, {
  method: "GET",
  headers,
});
const courses = await res.json();
```

## API Endpoints

The Andamio Gateway provides endpoints for:

| Category | Base Path | Description |
|----------|-----------|-------------|
| Auth | `/api/v2/auth/*` | Challenge/verify, JWT management |
| Courses | `/api/v2/course/*` | Course CRUD, modules, enrollments |
| Projects | `/api/v2/project/*` | Project CRUD, tasks, contributors |
| Transactions | `/api/v2/tx/*` | Build and register on-chain transactions |
| Global | `/api/v2/global/*` | Access tokens, platform config |

For transaction building and submission, see [Transaction Handling](/docs/guides/developers/transactions).

## Environment URLs

| Environment | Gateway URL | Use Case |
|-------------|-------------|----------|
| Production | `api.andamio.io` | Live applications |
| Development | `dev-api.andamio.io` | Local development on preprod |

## Error Responses

API errors return JSON with `error` and `message` fields:

```json
{
  "error": "UNAUTHORIZED",
  "message": "Invalid or expired JWT"
}
```

Common error codes:

| Code | Meaning |
|------|---------|
| `UNAUTHORIZED` | Missing or invalid auth headers |
| `FORBIDDEN` | User lacks permission for this action |
| `NOT_FOUND` | Resource doesn't exist |
| `VALIDATION_ERROR` | Invalid request body |
| `TX_BUILD_FAILED` | Transaction building failed |

See [Error Handling](/docs/guides/developers/error-handling) for recovery patterns.
