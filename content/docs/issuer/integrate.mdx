title: Integrate via API
description: How Andamio Issuer plugs into the systems you already run

Andamio Issuer is one REST API that you call from the systems you already run. Andamio builds each transaction, the person taking the action signs it with a social login or a browser wallet, and Andamio adds its sponsorship when you submit. Nobody holds ADA.

The [Issuer API reference](https://api.andamio.io/issuer/v1/docs/index.html) has every route with its full request and response schema.

## The shape

**One namespace, `/issuer/v1`.** Mainnet is at `https://api.andamio.io/issuer/v1` and preprod at `https://preprod.api.andamio.io/issuer/v1`. Your key decides the network.

**Authentication.** Send your enterprise key in the `X-API-Key` header. It is the only credential the routes take, with no end-user token. A developer key gets `403`.

**Writes (`POST`).** Paths name the transaction being built, such as `/courses/create` or `/courses/{course_id}/credentials/claim`. The response shape tells you what to do next:

- `POST /accounts/create` returns a `tx_hash`. Andamio has already built, sponsored and submitted it, and nobody signs.
- Every other write returns an `unsigned_tx`. The wallet that holds the acting alias (the `alias` in the request body) signs it, and you send it to `POST /submit`. Andamio adds its sponsorship and submits it.

There is no transaction-status route. Poll a read until the result shows. [Actions](/docs/issuer/actions) lists each write, who signs it and which read to poll.

**Reads (`GET`).** Courses, credentials, teachers, learners, and per-account views of credentials, submissions, reviews and activity. Results are always limited to the courses your key holds. Snapshot lists page with `page` and `limit`. Activity feeds page with an opaque `cursor`. `limit` defaults to 25, with a maximum of 100.

## Errors

Errors return an `error` object with a `code` and a `message`. The `code` is stable, so match on it rather than on the message.

| Code | Meaning |
|---|---|
| `402 QUOTA_EXHAUSTED` | Your plan has no allocation left for this action |
| `402 ACCOUNT_DISABLED` | Your enterprise account is disabled |
| `403 COURSE_NOT_AUTHORIZED` | Your key does not hold this course |

An error on a limit can name internal fields, such as `modules_to_add`, instead of the reference's `credentials_to_add`.

## How it relates to the Andamio API

Issuer is a higher-level surface built on the [Andamio API](/docs/api/getting-started). The API gives developers the full protocol, and they fund their own transactions. Issuer narrows it to the credentialing job and sponsors every transaction. If you want lower-level control or are building something beyond credential issuance, build on the API directly.

Questions about an integration go to [Support](/docs/issuer/support).
