This page is for developers who integrate Andamio Issuer into your systems. It follows [Roles and actions](/docs/issuer/actions): read that first for the access token, the roles and the credential loop. Here, each action gets its request, who signs it and what to read when it is done.

Work through it on preprod before you go live on mainnet. The [Issuer API reference](https://api.andamio.io/issuer/v1/docs/index.html) has every route with its full request and response schema.

## Connect

Andamio Issuer is one REST API under one namespace, `/issuer/v1`.

This page documents the Andamio Issuer API served by Andamio API 2.7.0. `/issuer/v1` only gains routes, optional fields, enum values and error codes, so handle a value you do not recognize. Any other change ships under a new path version, such as `/issuer/v2`. `GET /api/health` on either host returns the release it serves.

| Network | Base URL |
|---|---|
| Preprod | `https://preprod.api.andamio.io/issuer/v1` |
| Mainnet | `https://api.andamio.io/issuer/v1` |

Your key decides the network. Send your Andamio Issuer API key in the `X-API-Key` header on every request. It is the only key the routes take, with no end-user token. A developer key gets `403`. Send every write's body as JSON with `Content-Type: application/json`. Without that header the body is read as invalid JSON, and the request gets `400` with code `BAD_REQUEST`.

Check the key before anything else with `GET /config`:

```bash
curl https://preprod.api.andamio.io/issuer/v1/config \
  -H "X-API-Key: $ANDAMIO_API_KEY"
```

A working key returns `200`:

```json
{
  "data": {
    "project_id": "<project id>",
    "network_id": "preprod"
  }
}
```

`network_id` is `preprod` or `mainnet`, and it should match the network you expect. `project_id` is the value [social login](#go-live-with-social-login) needs. A `401` means the key is missing or invalid. A `503` means Andamio could not check the key: try again in a minute.

`GET /quota` shows what is left of your plan limits. The **Usage** tab at [issuer.andamio.io](https://issuer.andamio.io) shows the same.

For preprod, set up three CIP-30 browser wallets, one each for a course owner, a teacher and a learner. They need no ADA. The examples below use the aliases `acme-owner`, `acme-teacher` and `acme-learner`.

## Give each person an access token

Call this once for each person, with their wallet's address as `receiver_address`.

```http
POST /accounts/create
{ "alias": "acme-owner", "receiver_address": "addr_test1..." }
```

An alias is 1 to 31 ASCII characters. Andamio builds, sponsors and submits this one itself, and returns a `tx_hash`. Nobody signs. Poll `GET /addresses/{address}/accounts` until the alias appears. `GET /accounts/{alias}/availability` tells you first whether an alias is free.

## Run the six actions

Each of these returns an `unsigned_tx` and runs the [credential loop](/docs/issuer/actions#the-credential-loop). A build answers `200` with the unsigned transaction as hex:

```json
{ "unsigned_tx": "84a700d90102..." }
```

`POST /courses/create` also returns `course_id`, and `POST /courses/{course_id}/credentials/create` also returns `credential_hashes`.

1. The wallet that holds the acting alias, the `alias` in the request body, signs it as a partial signature (CIP-30 `signTx` with `partialSign` set to `true`). [Sign and submit](#sign-and-submit) shows how.
2. Send the signed transaction hex to `POST /submit` as `tx`. Andamio adds its sponsorship, submits it and returns the `tx_hash`.
3. Poll the read each action names until the result shows. There is no transaction-status route. `GET /accounts/{alias}/activity` shows every event for an account with its transaction hash, so it works as a poll for any action.

### Sign and submit

With Mesh 1.9, a wallet's `signTx` with `partialSign` set to `true` returns the full signed transaction:

```ts
import { BrowserWallet } from "@meshsdk/core";

const wallet = await BrowserWallet.enable(walletName);
const signedTx = await wallet.signTx(unsignedTx, true);
```

Raw CIP-30 `signTx` returns only a witness set. Add its signatures to the witnesses the transaction already carries, and keep those. Do not re-encode the transaction body: `POST /submit` finds your build by the hash of the body bytes, so a re-encoded body gets `404 BUILD_NOT_FOUND`. `@meshsdk/core-cst` does this for you:

```ts
import { addVKeyWitnessSetToTransaction } from "@meshsdk/core-cst";

const api = await window.cardano[walletName].enable();
const witnessSet = await api.signTx(unsignedTx, true);
const signedTx = addVKeyWitnessSetToTransaction(unsignedTx, witnessSet);
```

Then send `signedTx` from your server, where your API key stays:

```http
POST /submit
{ "tx": "84a700d90102..." }
```

It answers `200` with `{ "tx_hash": "..." }`.

### 1. Create a course

The course owner signs.

```http
POST /courses/create
{ "alias": "acme-owner", "teachers": ["acme-teacher"] }
```

The response carries the new `course_id`. Poll `GET /courses/{course_id}` until the course returns. Until the course is indexed, usually about a minute, the poll answers `404 COURSE_NOT_FOUND`, so keep polling. `teachers` is required: one to 10 aliases. Include the owner's alias if the owner teaches.

### 2. Name the teachers

The course owner signs. Use this to add or remove teachers after the course exists.

```http
POST /courses/{course_id}/teachers
{ "alias": "acme-owner", "teachers_to_add": ["acme-teacher-2"], "teachers_to_remove": [] }
```

`teachers_to_add` takes at most 30 aliases. An alias may appear only once across `teachers_to_add` and `teachers_to_remove`. A course can have at most 30 Teachers.

Poll `GET /courses/{course_id}/teachers` until the list shows the change.

### 3. Define a credential

A teacher signs.

```http
POST /courses/{course_id}/credentials/create
{
  "alias": "acme-teacher",
  "credentials_to_add": [
    {
      "slts": ["Completed security awareness training"],
      "allowed_student_state_ids": [],
      "prereq_credential_hashes": []
    }
  ]
}
```

The response carries `credential_hashes`, one for each definition, in the same order as `credentials_to_add`. Poll `GET /courses/{course_id}` until the credential is listed with a `defined_tx`. [How it works](/docs/issuer/how-it-works) has the rules for a statement.

To take a definition out of a course, a teacher signs `POST /courses/{course_id}/credentials/remove` with the hashes to remove. Nothing can be edited.

### 4. Submit evidence

The learner signs.

```http
POST /courses/{course_id}/credentials/{credential_hash}/evidence/submit
{ "alias": "acme-learner", "evidence_info": "<hash of the learner's evidence>" }
```

`evidence_info` is up to 140 characters, written to the chain as sent. Send a hash of the evidence, or a public URL if the evidence is already public, and never personal data. Poll `GET /accounts/acme-learner/submissions` until the submission shows with status `pending`. Until it is accepted, the learner can replace it with `.../evidence/update`.

### 5. Accept evidence

A teacher signs. Accept takes a batch of learners: `approvals` lists 1 to 30 aliases, each one once.

```http
POST /courses/{course_id}/credentials/evidence/approve
{ "alias": "acme-teacher", "approvals": ["acme-learner"] }
```

Poll `GET /courses/{course_id}/credentials/issuances` until the learner shows an `approved_tx`. Each learner accepted counts against your plan's Credentials limit.

The batch is all or nothing. If any learner in it was already assessed or has no submission, the whole batch fails. The error does not name those learners: find them with `GET /accounts/{alias}/reviews?status=pending` and the Teacher's alias.

### 6. Claim the credential

The learner signs.

```http
POST /courses/{course_id}/credentials/claim
{ "alias": "acme-learner" }
```

Poll `GET /accounts/acme-learner/credentials` until the credential is listed with a `claimed_tx`. The learner now holds the credential, and claiming unenrolls them from the course.

## Go live with social login

In production, most people sign with a social login instead of a browser wallet. Social login uses the `project_id` from `GET /config`, and it works only on a sign-in domain Andamio has allowlisted. Register your domain early, as [Before you start](/docs/issuer/before-you-start) describes.

## Reads

Reads cover courses, credentials, teachers, learners, and per-account views of credentials, submissions, reviews and activity. Results are always limited to the courses your key holds.

These are every read. **Paged** lists take `page` and `limit`. The one **cursor** feed takes `cursor` and `limit`. [Paging](#paging) shows both.

### Account reads

| Route | Returns | Paging |
|---|---|---|
| `GET /accounts/{alias}/availability` | Whether an alias is free | |
| `GET /addresses/{address}/accounts` | The aliases held at a wallet address | |
| `GET /accounts/{alias}/courses` | Courses the account owns, teaches or is enrolled in. Filter with `relationship` | Paged |
| `GET /accounts/{alias}/credentials` | Credentials the account holds, with their `claimed_tx` | Paged |
| `GET /accounts/{alias}/submissions` | The account's evidence submissions and their status. Filter with `status` | Paged |
| `GET /accounts/{alias}/reviews` | Submissions to assess in the courses the account teaches. Filter with `status` and `course_id` | Paged |
| `GET /accounts/{alias}/activity` | Every on-chain event for the account, with its transaction hash. Filter with `role` and `course_id` | Cursor |

### Course reads

| Route | Returns | Paging |
|---|---|---|
| `GET /courses` | Your courses, with owner and creation transaction | Paged |
| `GET /courses/{course_id}` | One course and the credentials it defines | |
| `GET /courses/{course_id}/teachers` | The course's current Teachers | Paged |
| `GET /courses/{course_id}/learners` | Enrolled learners. A learner who claims a credential leaves this list and shows in issuances | Paged |
| `GET /courses/{course_id}/stats/teachers` | For each Teacher: credentials defined, assessments accepted and rejected, and when last active | Paged |

### Credential reads

| Route | Returns | Paging |
|---|---|---|
| `GET /courses/{course_id}/credentials/issuances` | Each learner and credential accepted, with `approved_tx`, and `claimed_tx` once claimed. Filter with `claimed` | Paged |

### Other reads

| Route | Returns | Paging |
|---|---|---|
| `GET /config` | Your `project_id` and `network_id` | |
| `GET /quota` | What is left of your plan limits | |

### Paging

A paged list takes `page`, starting at 1, and `limit`, which defaults to 25 with a maximum of 100. It returns the page in `meta.pagination`:

```json
{
  "data": [
    { "alias": "acme-teacher", "added_at": "2026-11-02T10:15:00Z", "added_tx": "<tx hash>" }
  ],
  "meta": { "pagination": { "page": 1, "page_size": 25, "total": 1 } }
}
```

`page_size` is the page size that applied, and `total` counts the items across every page.

`GET /accounts/{alias}/activity` is the one cursor feed. Its `limit` also defaults to 25, with a maximum of 100. It returns:

```json
{
  "data": [
    {
      "kind": "evidence_submit",
      "actor": "acme-learner",
      "course_id": "<course id>",
      "credential_hash": "<credential hash>",
      "submission_author": "acme-learner",
      "slot": 109283746,
      "timestamp": "2026-11-20T09:30:00Z",
      "tx_hash": "<tx hash>"
    }
  ],
  "meta": { "pagination": { "next_cursor": "<cursor>", "has_more": true } }
}
```

For the next page, send `next_cursor` back as `cursor`, exactly as you got it. The cursor is opaque, so do not build or change one. `next_cursor` is left out when there is none. On the last page, `has_more` is `false`.

## Errors

Errors return an `error` object with a `code` and a `message`. The `code` is stable, so match on it, never on the `message`. The `message` tells you what happened and what to do next.

For example, `POST /submit` with a transaction nobody signed answers `400`:

```json
{
  "error": {
    "code": "MISSING_SIGNATURE",
    "message": "This transaction has no signature. Sign it with the wallet that owns the alias in your build request."
  }
}
```

The tables below are a selection: the codes you are most likely to meet while you run the six actions. The API answers other codes too, and `/issuer/v1` can gain new ones, so your program must handle a code it does not recognize. The [Issuer API reference](https://api.andamio.io/issuer/v1/docs/index.html) lists every code each route can answer.

### Any route

| Code | Cause and what to do |
|---|---|
| `400 BAD_REQUEST` | The request is malformed, or breaks a rule the API checks before it builds, such as the length of a list. Fix the request as the message says |
| `401 UNAUTHORIZED` | The API key is missing, or not valid on this host. Check the key and the network |
| `403 FORBIDDEN` | The key is not an Andamio Issuer API key. Use your Andamio Issuer API key |
| `422 UNPROCESSABLE_ENTITY` | The request breaks a rule that has no code of its own. The message names the rule, such as the limit of 30 Teachers on a course, or a value in `allowed_student_state_ids` that is not in the course. Fix the request as the message says |
| `500 INTERNAL_SERVER_ERROR` | An unexpected fault at Andamio. Contact [Support](/docs/issuer/support) with the `X-Request-Id` header from the response |
| `502 BAD_GATEWAY` | Andamio could not fetch the data, or could not build or sponsor the transaction. Your request is fine, and nothing was charged. Try again in a minute. If it keeps failing, contact [Support](/docs/issuer/support) with the `X-Request-Id` header from the response |
| `503 SERVICE_UNAVAILABLE` | Andamio, or a service it depends on, could not answer. Try again in a minute. A `503` with any other code is not a reason to retry: follow that code's row |

### Courses

Today, a course outside your account answers `404 COURSE_NOT_FOUND` on a read and `403 COURSE_NOT_AUTHORIZED` on a write.

| Code | Cause and what to do |
|---|---|
| `403 COURSE_NOT_AUTHORIZED` | A write on a course outside your account. Use a course your account owns |
| `404 COURSE_NOT_FOUND` | A read of a course outside your account, or a course that is not indexed yet. A course you just created answers this until it is indexed, usually about a minute, so keep trying |

### Every build

These answer the six actions when they build, and `POST /accounts/create` too, apart from `404 ALIAS_NOT_FOUND`. `402 QUOTA_EXHAUSTED` answers every build except claiming and removing a credential. Both `402` codes can also answer `/submit`.

| Code | Cause and what to do |
|---|---|
| `402 QUOTA_EXHAUSTED` | Your plan's limit for this action is used up. Creating an account needs Participants, creating a course needs Courses, and the other builds need Credentials |
| `402 ACCOUNT_DISABLED` | Your Andamio Issuer account is disabled, or the key has no account. Contact [Support](/docs/issuer/support) |
| `404 ALIAS_NOT_FOUND` | No account has this alias. An account you just created answers this on every build until it is on chain, usually about a minute, so keep trying. Otherwise, correct the alias or create the account |
| `422 TRANSACTION_TOO_LARGE` | The request does not fit in one transaction. Send fewer items |
| `503 SPONSORSHIP_UNAVAILABLE` | Sponsorship is not configured on this host. Retrying will not help. Contact [Support](/docs/issuer/support) |

### Submit

These answer `POST /submit`. Some of the same codes answer `POST /accounts/create` with a different next step: see [Accounts](#accounts).

| Code | Cause and what to do |
|---|---|
| `400 MISSING_SIGNATURE` | The transaction carries no signature. Sign it with the acting wallet |
| `400 TRANSACTION_FAILED` | The transaction could not be submitted. Check that the wallet holding the acting alias signed it. If it did, the state changed since the build, so read again and build again |
| `404 BUILD_NOT_FOUND` | Andamio has no record of building this transaction. Build it again |
| `409 ALREADY_SUBMITTED` | This transaction was already submitted. Check `GET /accounts/{alias}/activity` to confirm it took effect |
| `410 BUILD_EXPIRED` | An unsigned transaction must be signed and submitted within 2 hours of being built. Build it again |
| `502 SUBMISSION_ERROR` | Andamio could not tell whether the transaction was submitted. Wait a minute, then check `GET /accounts/{alias}/activity`. If the action is not there, build it again |

### Evidence and claim

| Code | Cause and what to do |
|---|---|
| `404 CREDENTIAL_NOT_FOUND` | The credential is not in this course. Check `GET /courses/{course_id}` |
| `422 PREREQUISITES_NOT_MET` | On submit, the learner has not earned the credentials this one requires. They earn those first |
| `422 CREDENTIAL_ALREADY_EARNED` | On submit, the learner already earned this credential. Nothing more to do |
| `422 EVIDENCE_UNCHANGED` | On submit or update, the learner already submitted this evidence, so nothing changed |
| `422 NO_OPEN_SUBMISSION` | On update, the learner has no open submission: check `GET /accounts/{alias}/submissions` with the learner's alias. On accept, at least one learner in `approvals` has no open submission, so the whole batch failed: check `GET /accounts/{alias}/reviews?status=pending` with the teacher's alias |
| `422 NOTHING_TO_CLAIM` | On claim, the learner is not enrolled in this course, or already claimed |

### Teachers

A course can have at most 30 Teachers. A change that would go past that answers `422 UNPROCESSABLE_ENTITY`, as in [Any route](#any-route).

| Code | Cause and what to do |
|---|---|
| `409 TEACHER_NOT_IN_COURSE` | An alias in `teachers_to_remove` is not a Teacher of this course. Check `GET /courses/{course_id}/teachers` |
| `422 OWNER_NOT_ALLOWED` | Only the course owner can change Teachers. Use the course owner's alias |
| `422 TEACHER_ALREADY_EXISTS` | An alias in `teachers_to_add` is already a Teacher of this course. Drop it, or check `GET /courses/{course_id}/teachers` |
| `422 TEACHER_NOT_ALLOWED` | On defining or removing a credential, or accepting evidence, the acting alias is not a Teacher of this course. A Teacher added in the last minute may not count yet. Otherwise, use a Teacher's alias |

### Accounts

These answer `POST /accounts/create`. Andamio submits this request itself, so a code it shares with `/submit` calls for a different next step here.

| Code | Cause and what to do |
|---|---|
| `400 TRANSACTION_FAILED` | The request could not be submitted, so the account was not created. Send it again |
| `404 BUILD_NOT_FOUND` | Andamio could not finish this request. Send it again |
| `409 ALIAS_NOT_AVAILABLE` | This alias is taken. Choose a different one |
| `409 ALREADY_SUBMITTED` | Andamio has already seen this request. Check `GET /addresses/{address}/accounts` to confirm the account was created |
| `410 BUILD_EXPIRED` | Andamio could not finish this request. Send it again |
| `502 SUBMISSION_ERROR` | Andamio could not tell whether the account was created. Wait a minute, then check `GET /addresses/{address}/accounts`. If the alias is not there, send the request again |

## How it relates to the Andamio API

Issuer and the [Andamio API](/docs/api/getting-started) are separate products with separate keys, both built on the [Andamio Protocol](/docs/protocol). Issuer covers issuing credentials and sponsors every transaction. The Andamio API gives developers the whole protocol, and they decide who funds each transaction. If you are building something beyond credential issuance, use the Andamio API.

Questions about an integration go to [Support](/docs/issuer/support).
