# Update Assignment

Student updates their assignment submission with new information while keeping the same SLT hash.

## API Endpoint

```
POST /tx/v2/student/course/assignment/update
```

## Cost Breakdown

| Component | Amount |
|-----------|--------|
| Transaction Fee | ~0.28 ADA |
| MinUTxO Delta | ~0.05 ADA |
| Service Fee | 0 ADA |
| **Total Wallet Delta** | **~0.33 ADA** |

The minUTxO increases when the datum grows (longer assignment_info string).

## Request Body

```json
{
  "walletData": {
    "usedAddresses": ["addr_test1..."],
    "changeAddress": "addr_test1..."
  },
  "alias": "student_001",
  "courseId": "23a6bbce3a8deca8985764e847594f6956c9dc643e3f6c8efdba04e4",
  "assignmentInfo": "Updated assignment submission with more details",
  "maybeNewSltHash": "8dcbe1b925d87e6c547bbd8071c23a712db4c32751454b0948f8c846e9246b5c"
}
```

The `maybeNewSltHash` field is optional. If omitted, only the assignment info is updated while keeping the same SLT hash.

## Transaction Pattern

**Spend and Recreate** - No minting. Consumes and recreates course state UTxO with updated datum.

## Inputs

| ID | Type | Validator | Description |
|----|------|-----------|-------------|
| student_access_token | wallet | - | Student's access token for auth |
| student_course_state | script | course-state-validator | Student's course state (spent) |
| student_wallet | wallet | - | Student wallet for fees |

## Outputs

| ID | Type | Validator | Value | Description |
|----|------|-----------|-------|-------------|
| student_access_token_return | wallet | - | ~1.17 ADA + access token | Student retains access token |
| course_state_updated | script | course-state-validator | ~1.50 ADA + course state token | **Updated assignment info** |

## Datum Changes

Only the `assignment_info` field changes - the SLT hash remains the same:

**Before:**
```json
{
  "constructor": 1,
  "fields": [
    { "bytes": "<slt_hash>" },
    { "bytes": "original info" },
    { "list": [] }
  ]
}
```

**After:**
```json
{
  "constructor": 1,
  "fields": [
    { "bytes": "<slt_hash>" },
    { "bytes": "updated assignment info" },
    { "list": [] }
  ]
}
```

## Redeemer

Constructor 1 with nested constructor 0 for the update action:

```json
{
  "constructor": 1,
  "fields": [{
    "constructor": 0,
    "fields": [
      { "bytes": "<slt_hash>" },
      { "bytes": "<new_assignment_info>" }
    ]
  }]
}
```

## Reference Inputs

| ID | Description |
|----|-------------|
| module_ref | Module reference for SLT validation |

## Notes

- SLT hash is **unchanged** between input and output
- Datum stays as constructor 1 (pending assignment state)
- MinUTxO increases when assignment_info grows (student pays the difference)
- No service fee for assignment updates
- Student must own the course state token being updated
