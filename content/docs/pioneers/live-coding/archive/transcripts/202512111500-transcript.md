Summary
James Dunseith announced the soft launch of the Andamio Pioneers program, with an official launch in January, to test systems and collaborate on version two of the Andamio protocol and platform, which includes both on-chain and off-chain improvements. The program emphasizes "building in public," reminiscent of early Gimbal Labs, and James Dunseith, with participants including Newman Lanier, Lewis Nduati, and Tevo Kask, began organizing the project on GitHub, sharing documentation, and confirming the session's technical goal was for attendees to access and run the T3 app template. The discussion explored the technical infrastructure, noting the temporary use of three separate environment variables before the unified Andamio API launch, the philosophical questions surrounding tracking contributor credit (raised by Shaggyrax) and the "source of truth" between the database and the Cardano blockchain, and the extensive use of agent-generated code (Claude) in developing the T3 app template and its documentation.

Soft Launch of Andamio Pioneers Program: James Dunseith announced the soft launch of a new initiative, the Andamio Pioneers program, noting that they only had an hour for the current meeting but would be doing this very frequently in the months to come (00:05:11). The official launch is scheduled for January, and the soft launch serves to test systems and start building with friends. Building in Public and Gimbal Labs History: The soft launch is a "reclaiming of part of what we were doing at Gimbal Labs in the very early days," specifically relating to the first code for what would become Andamio, which was built at Gimbal Labs in 2021. James Dunseith described Gimbal Labs' special job of combining discussions about technical and social or philosophical questions, referencing past explorations of use cases like concert ticketing (00:07:41). In 2026, Andamio is taking this on, investigating how the system works, what can be built upon it, and the meaning of having these new tools. James Dunseith expressed excitement to turn this lens on Andamio and do what has been done together for years, inviting collaboration, leadership, and ideas for evolving the program, as Andamio is an open and permissionless system (00:09:03). Newman Lanier was "pretty stoked" about this direction, particularly the return to "building in public" (00:16:31).
Accessing Documentation and Tools: The team will be working from the Andamio documentation, with the link shared in the chat. The documentation has a section for the Andamio Pioneers program (00:06:27). James Dunseith indicated that they will use GitHub for project management. Attendees were asked to share their Discord handles to be added to a GitHub team and repository (00:10:12). They are using Google Meet for easy recording and sharing of the transcript in a simple Google Doc, which will be stored in the live coding archive within the documentation (00:11:16). Technical Goal and Environment Variables: The technical goal for the day is for everyone to be able to pull down the code for the Andamio T3 app template, grab the environment variables, and start using it (00:11:16). James Dunseith explained the current status of the APIs, noting that right now there are three separate data sources in the environment variables: a database API URL, an Andamio scan, and a prepro v2 transaction API. However, when Andamio v2 publicly launches on mainnet, all three data sources will be wrapped up in a single Andamio API (00:17:29). The Andamio database handles most functions of the previous Andamio v1 database, while Andamio scan is a major upgrade for indexing on-chain data, offering improvements in performance and developer ease of use. The transaction API is also a major improvement in developer experience, performance, and on-chain cost, though both the scan and transaction endpoints are still in development, with new endpoints to be released over the next few weeks (00:18:45).
T3 App Template and Modularity: The T3 app template is a temporary solution to play around with the current endpoints. Once the unified Andamio API is ready, a little cleanup will be necessary in the T3 app template to ensure compatibility. James Dunseith noted this update process is "annoying busy work," highlighting the need for modular code with minimal repetition to make changes easy (00:20:05). The T3 app template is currently a T3 app template but could function as a NextJS template for now, as they are not currently using its built-in database schema capabilities. The template is extensible for those who want to run their own database or build a new one using TRPC (00:21:15). The template is MIT licensed, and the goal is for it to be fully open-sourced, well-documented, and accessible by January (00:22:24).
Agentic Tools and Documentation in the T3 Template: James Dunseith showcased the use of agentic tools, noting that the template is structured to support "agentup supported development" (00:20:05). The repository includes a `claude` directory with a `claude.md` file, which is machine-readable documentation of the app template (00:22:24). The file, along with other all-caps markdown files, provides documentation that is agent-generated and agent-readable. This is intended to give agents (like Claude, ChatGPT, Gemini, etc.) as much context as possible, allowing people to build using whatever modality is most effective for them (00:23:43). James Dunseith suggested exploring the philosophical question of when it is a good idea to "vibe code" and what conversations can be had with an agent running in the background (00:25:00).
Agent-Generated Codebase: James Dunseith revealed that the entire T3 app template was an experiment in having Claude build the application. The Andamio development team has only written "a couple dozen lines of code". This was achieved by painstakingly building and refining context for the agent, which allowed it to implement features quickly (00:26:26). The front-end code is almost entirely agent-generated, evidenced by the detailed comments that James Dunseith noted they typically lack time to write (00:27:43).
Tracking Contributor Credit with AI: Shaggyrax raised a question about tracking contributors, asking if there should be a methodology to notate if a contribution was made using an agent like Claude versus manually added code (00:29:06). James Dunseith stated they did not have a strong opinion and that this is a philosophical question to explore (00:30:04). Currently, there are no rules, but James Dunseith noted they do not stop the agent from giving itself credit if they ask it to make a Git commit (00:31:17). James Dunseith confirmed that the launch in January will include a treasury with tokens to reward contributors (00:30:04).
New NPM Packages and Agentic Coding: The T3 app template depends on two new NPM packages, both at version 040 for testing. The `DB API` package provides types for connecting to the Andamio DB API, and the `Andamio transactions` package contains definitions for the transactions used in the project. These packages were created with "agentic coding" in mind (00:31:17). James Dunseith showed the `Andamio transactions` package, noting it is part of a mono repo and uses a `package.json` file for naming (00:32:19).
Transaction Definitions for Agent Use: The `Andamio transactions` package contains high-level definitions for various transactions like `mint access token`, `create course`, and `enrollment transaction`. The `enrollment transaction` definition shows a data structure that tracks required parameters to build the transaction, parameters needed to run database side effects upon submission or confirmation, and the corresponding endpoints (00:33:49). This careful definition work allowed the agent (Claude) to build the entire front end of the T3 template effectively (00:35:05).
Database API Package and Type Import: The `Andamio database API` source code is separate but located in the same mono repo. The package for the DB API provides types for all endpoints (00:32:19) (00:36:36). James Dunseith demonstrated how importing the package allows for "really nice types" that enable IntelliSense and code completion, showing an example of importing `course output` and `listing the course modules` (00:38:13).
Current Agenda and Focus Areas: The current agenda includes collecting GitHub handles, getting access to and running the T3 app template locally, and submitting any identified changes as issues to the GitHub repo. The documentation has a "focus areas" section that serves as a "live workbench," listing things the team is currently working on, such as transaction cost verification, reconstructing on-chain data, and v2 transaction parsing (00:39:36). Tevo Kask asked if this focus area documentation was AI generated or manual. James Dunseith explained that they define what should be there, but they ask the agent to review and maintain the documentation, such as updating which transaction costs have been checked (00:41:36).
Template Demonstration and Login Issues: James Dunseith demonstrated the running T3 app template locally. The landing page was built based on Claude's understanding of the project (00:44:13). Attempting to log in initially resulted in issues due to switching wallet accounts. Upon successful login, the dashboard showed messy, unstyled data, including the connected address and confirmation that an access token had been minted on prepro (00:45:15). Users are assumed to know how to connect a wallet like Eternal to the pre-production test net (00:46:37).
Course Management and On-Chain/Off-Chain Status: In the course studio, three courses were listed. One course was "confirmed on chain" and had a name, while the other two said "not in database". James Dunseith then showed the Andamio scan swagger documentation, which, despite having few endpoints, offers significant functionality (00:47:43). The "get all users" endpoint showed a short list, reflecting that Andamio V2 is brand new on prepro. Nelson Kshetrimayum noted that slow updates to the user list endpoint might be due to a down do instance (00:48:52). Transaction API Demonstration: The transaction API was demonstrated, showing an endpoint where a course admin can create a new course (00:50:08). Adrian intervened to clarify that the `wallet data` object (containing used addresses and change address) is optional when building a transaction, as the alias is sufficient (00:51:16). James Dunseith then executed a query to create a course using the simplified endpoint, which returned an unsigned TX Cbor string and the new course ID (00:52:50). James Dunseith demonstrated how this unsigned Cbor could be copied and imported into an Eternal wallet for signing, illustrating how the API simplifies the complexity of building the full transaction infrastructure (00:54:03).
Data Synchronization and Source of Truth: James Dunseith confirmed that the named course, "Andamio 101," was in the database (off-chain) and matched the policy ID (23 A6) of one of the on-chain courses listed by Andamio Scan (00:55:28). The untitled courses in the studio were confirmed to exist on-chain (e.g., policy ID 68396F) but were not yet in the database (00:58:01). This led to a philosophical question regarding on-chain data reconstruction: which is the "source of truth," the database instance or the Cardano blockchain? The UX attempts to address this by showing options like "import a course" or "save a title" for an on-chain artifact not yet in the database (00:59:34). James Dunseith noted that saving a title to the database did not change anything on chain, posing a point for reflection (01:00:58).
Building in Public Scheduling and Availability: James Dunseith stated that building in public can sometimes be difficult to schedule and expressed the intention to provide some warning and commit to at least the Wednesday sessions, noting that this arrangement works well for them. The speaker invited anyone for whom the Wednesday times offered do not work to reach out so that other possible times could be explored together. James Dunseith also mentioned that inspiration can strike at any moment and cannot be scheduled, so there will be times when they will jump into the Andamio network Discord to "build in public". The speaker clarified that this does not require others to drop everything and join, but rather is an invitation for those who are around and wish to stop by. James Dunseith strongly advised participants not to feel obligated to attend those spontaneous sessions and to avoid setting notifications for them, instead emphasizing that the Andamio network Discord server is a welcoming space for people to drop by and engage in activities, which is where James Dunseith intends to be doing work. The speaker concluded this point by stating that they will do their best, but that scheduling when these sessions are going to run is not always possible (01:02:50).
